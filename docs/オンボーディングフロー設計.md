# オンボーディングフロー設計

## 📋 概要

新規ユーザーのアカウント作成時に、ゲームタイトル選択 → おすすめ配信者選択 → お気に入り登録を行うフロー。

---

## 🔍 Twitch API 調査結果

### 使用するエンドポイント

| ステップ | エンドポイント | 用途 | レスポンス例 |
|---------|---------------|------|-------------|
| 1 | `GET /helix/games/top` | 人気ゲームタイトル一覧取得 | 視聴者数順にソート済み |
| 2 | `GET /helix/streams` | ゲーム別の配信者検索（現在配信中） | ライブ配信中の配信者 |
| 3 | `GET /helix/videos` | 配信者のアーカイブ取得 | 視聴数でソート可能 |

---

## 📊 ステップ1: ゲームタイトル選択

### UI仕様

**選択方式: ラジオボタン（1つのみ選択）**
- 複数選択は現時点で実装しない
- 理由: 複数ゲーム選択時のメリットが不明確
- 将来的な拡張として検討可能

### API: `GET /helix/games/top`

```typescript
// エンドポイント
GET https://api.twitch.tv/helix/games/top?first=50

// レスポンス
{
  "data": [
    {
      "id": "516575",
      "name": "VALORANT",
      "box_art_url": "https://static-cdn.jtvnw.net/ttv-boxart/516575-{width}x{height}.jpg"
    },
    {
      "id": "32982",
      "name": "Grand Theft Auto V",
      "box_art_url": "https://static-cdn.jtvnw.net/ttv-boxart/32982-{width}x{height}.jpg"
    },
    // ...
  ]
}
```

### 推奨実装

**❌ 全ゲーム取得は不要**
- Twitch には数万のゲームが存在
- ユーザーにすべて見せるのは UX が悪い

**✅ 人気Top 50ゲームに絞る**
- `first=50` パラメータで取得
- Twitch が視聴者数順にソート済み
- API呼び出しは**1回のみ**

### 取得タイミング

**推奨: モーダル開いた瞬間に取得**

```typescript
// components/onboarding/game-selection-step.tsx
'use client';

export function GameSelectionStep() {
  const [selectedGameId, setSelectedGameId] = useState<string>('');

  const { data: games, isLoading } = useQuery({
    queryKey: ['games', 'top'],
    queryFn: async () => {
      const res = await fetch('/api/games/top');
      return res.json();
    },
    staleTime: 10 * 60 * 1000, // 10分間キャッシュ（人気ゲームはそう変わらない）
  });

  // ラジオボタンでゲーム選択
}
```

**理由**:
- ゲーム一覧は50件なので軽い（1リクエスト）
- 10分間キャッシュすれば、他のユーザーも再利用可能
- ユーザーが検索入力する前に表示できる

## 📊 ステップ2: おすすめ配信者選択

### 要件
- 選択したゲームの**直近3日間のクリップ**
- **クリップ再生数が多い配信者**のTop 6人
- **日本の配信者のみ**

---

## 🎯 なぜクリップ再生数ベースを採用したか

### 技術的制約
- Twitch API には配信者アーカイブを期間で絞るクエリがない
- `/helix/videos` は配信者IDの指定が必須（ゲームIDでは検索不可）
- `/helix/clips` はゲームIDで直接取得可能 + 期間指定可能

### メリット
- APIリクエスト数が少ない（7回 vs 21回以上）
- 直近3日間の条件を満たせる
- クリップ再生数 = バズった瞬間 = 人気の指標として適切

### 代替案との比較
- **アーカイブ視聴数**: ゲームIDで配信者を検索できないため実装困難
- **現在配信中**: 期間指定ができない（今この瞬間のみ）
- **クリップ再生数**: ✅ 採用（上記メリット）

---

### 採用方法: クリップ再生数ベース

```typescript
// ステップ2-1: ゲームIDでクリップを取得（直近3日間、再生数順）
GET /helix/clips?game_id={game_id}&started_at={3日前}&ended_at={今}&first=100

// レスポンス例（再生数順に自動ソート済み）
{
  "data": [
    {
      "id": "clip123",
      "broadcaster_id": "12345",
      "broadcaster_name": "example_streamer",
      "game_id": "516575",
      "language": "ja",  // ← 言語情報
      "view_count": 50000,
      "created_at": "2025-11-17T12:00:00Z"
    },
    // ... 最大100件
  ]
}

// ステップ2-2: 日本語クリップのみフィルター
const jaClips = clips.data.filter(clip => clip.language === 'ja');

// ステップ2-3: 配信者ごとにクリップをグループ化 + 総再生数を計算
const broadcasterMap = new Map();
jaClips.forEach(clip => {
  if (!broadcasterMap.has(clip.broadcaster_id)) {
    broadcasterMap.set(clip.broadcaster_id, {
      clips: [],
      total_views: 0,
    });
  }
  const broadcaster = broadcasterMap.get(clip.broadcaster_id);
  broadcaster.clips.push(clip);
  broadcaster.total_views += clip.view_count;
});

// ステップ2-4: 総再生数でソートしてTop 6
const top6 = Array.from(broadcasterMap.values())
  .sort((a, b) => b.total_views - a.total_views)
  .slice(0, 6);

// ステップ2-5: プロフィール画像を取得（並列実行）
const results = await Promise.all(
  top6.map(async (broadcaster) => {
    const user = await getStreamerById(broadcaster.broadcaster_id);
    return { ...broadcaster, profileImage: user.profile_image_url };
  })
);
```

**メリット**:
- ✅ APIリクエスト数が少ない（1 + 6 = 7回）
- ✅ 直近3日間の条件を満たせる
- ✅ クリップ再生数 = バズった瞬間 = 人気の指標
- ✅ 処理が高速（1〜2秒）

**制約**:
- クリップAPIに `language` パラメータがないため、クライアント側でフィルター必要
- ただし100件取得すれば日本の配信者も十分含まれる

### 実装コード

```typescript
// app/api/recommendations/streamers/route.ts
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const gameId = searchParams.get('gameId');

  // 1. 現在配信中の配信者を取得（日本語、視聴者数順）
  const streams = await twitchApiRequest('/streams', {
    game_id: gameId,
    language: 'ja',
    first: '100',
  });

  // 2. 上位20人の配信者のアーカイブを並列取得
  const topBroadcasters = streams.data.slice(0, 20);

  const videoPromises = topBroadcasters.map(async (stream: any) => {
    try {
      const videos = await twitchApiRequest('/videos', {
        user_id: stream.user_id,
        period: 'week',  // 直近1週間
        sort: 'views',   // 視聴数順
        first: '5',
      });

      const totalViews = videos.data.reduce(
        (sum: number, video: any) => sum + video.view_count,
        0
      );

      return {
        userId: stream.user_id,
        userName: stream.user_name,
        userLogin: stream.user_login,
        profileImageUrl: stream.thumbnail_url,
        totalViews,
        recentVideos: videos.data,
      };
    } catch (error) {
      console.error(`Failed to fetch videos for ${stream.user_name}`, error);
      return null;
    }
  });

  const results = await Promise.all(videoPromises);
  const validResults = results.filter((r) => r !== null);

  // 3. 視聴数でソートしてTop 6
  const top6 = validResults
    .sort((a, b) => b.totalViews - a.totalViews)
    .slice(0, 6);

  return NextResponse.json({ data: top6 });
}
```

## ⚡ API Rate Limit 対策

### 制限
- **800リクエスト/分**（App Access Token使用時）

### このフローでのリクエスト数
```
ステップ1: ゲーム一覧取得
  └─ 1リクエスト

ステップ2: おすすめ配信者取得
  ├─ 現在配信中の配信者: 1リクエスト
  └─ 各配信者のアーカイブ: 20リクエスト（並列）
  = 合計 21リクエスト

総計: 22リクエスト
```

**結論: 全く問題なし**
- 800リクエスト/分の制限に対して、わずか22リクエスト
- 並列実行（`Promise.all`）で高速化可能
- React Query でキャッシュすれば、同じゲーム選択時は再利用可能

## 🎯 取得タイミングの推奨

### ステップ1 → ステップ2 の遷移時に取得（推奨）

```typescript
// GameSelectionModal.tsx
const handleNextStep = async () => {
  // ユーザーがゲームを選択して「次へ」を押した瞬間
  setCurrentStep('loading'); // ローディング表示

  // おすすめ配信者を取得
  const streamers = await fetchRecommendedStreamers(selectedGameId);

  setRecommendedStreamers(streamers);
  setCurrentStep('streamer-selection'); // 次のステップへ
};
```

**理由**:
- ゲーム選択前に配信者データを取得しても無駄（どのゲームを選ぶかわからない）
- 「次へ」を押した瞬間に取得すれば、ユーザーは待ち時間を許容できる
- 並列実行なので、20リクエストでも2〜3秒で完了

## ✅ まとめ

### Q1: ゲームタイトルは絞るべきか？
**A: はい。人気Top 50に絞る**
- 全ゲーム（数万件）は不要
- API 1回で取得可能
- ユーザー体験も向上

### Q2: ゲーム選択は複数可能にするべきか？
**A: いいえ。現時点では1つのみ（ラジオボタン）**
- 複数選択時のメリットが不明確
- 将来的な拡張として検討可能

### Q3: なぜクリップ再生数ベースか？
**A: 技術的制約とメリット**
- Twitch API には配信者アーカイブを期間で絞るクエリがない
- クリップはゲームIDで直接取得可能 + 期間指定可能
- APIリクエスト数が少ない（7回 vs 21回以上）
- クリップ再生数 = バズった瞬間 = 人気の指標

### Q4: 取得タイミングは？
**A: ステップ遷移時**
- ステップ1（ゲーム選択）: モーダル開いた瞬間に取得
- ステップ2（配信者選択）: 「次へ」押した瞬間に取得

### Q5: 並列取得は必要か？
**A: 必須**
- 6人分のプロフィール画像を並列取得（`Promise.all`）
- Rate Limit には余裕がある（800/分 vs 7リクエスト）
